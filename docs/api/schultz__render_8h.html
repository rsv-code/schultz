Detailed Description

Rendering a widget, or a whole window, into memory.

Part of the host facing interface. A host binds to schultz_api.h, which includes this header. The same tree that draws to a window draws to a buffer, at whatever resolution is asked for, without being laid out again. That is one call, and it is what a screenshot, a thumbnail, an image export and a printed page all want.

Pagination is not here and is not planned. Splitting a continuous tree across page boundaries needs to know what may be broken, what must stay together and what repeats as a heading, and those are document semantics a widget toolkit has no opinion about. An application that knows its own document lays out one page at a time and renders each with this.

The print dialog and the spooler are not here either, being wholly platform specific.

Renders a node and everything under it into a buffer.

The node is drawn at the buffer's top left whatever its position in the tree, so rendering one widget gives that widget and nothing around it. Pixels are premultiplied ARGB8888, the same layout the window buffer and schultz_image_set_pixels both use, so a render can be handed straight back as an image.

Text is rasterized at the scale asked for rather than scaled up from screen size, so a page at print resolution is sharp.

The caller need not have started the rendering engine; this starts it for the duration of the call and the count it keeps means doing so alongside a running window is safe.

Parameters
treeThe tree to render from. Must not be NULL.
nodeThe node to render. SCHULTZ_HANDLE_NONE means the root.
scalePixels to render for each one the node measures. Two gives a picture twice the size. Must be greater than zero.
optionsWhat to render with. Must not be NULL.
pixelsThe buffer to render into. Must not be NULL.
widthBuffer width in pixels. Must be greater than zero.
heightBuffer height in pixels. Must be greater than zero.
stridePixels per row, which may exceed the width. Zero means the rows are packed.
Returns
SCHULTZ_OK, SCHULTZ_ERR_INVALID_ARGUMENT for a bad argument, SCHULTZ_ERR_INVALID_HANDLE when the node is not live, or SCHULTZ_ERR_OUT_OF_MEMORY.

Renders a node straight to the bytes of a picture file.

What schultz_render_size, a buffer of your own, schultz_render_to_buffer and schultz_image_encode do together, in one call: the common case, which is wanting a PNG of a widget and not wanting the pixels for anything else.

Use the three calls separately when the pixels are the point: to render into a buffer you already have, to hand the result back through schultz_image_set_pixels, or to write more than one format from one render.

How large this gets is decided by the scale. A node measuring a thousand units on a side at a scale of one hundred asks for forty gigabytes of pixels before a single byte is encoded, so the size is worked out and refused first, before anything is allocated or drawn. Refusing afterwards would have spent exactly what the refusal is for.

Parameters
treeThe tree to render from. Must not be NULL.
nodeThe node to render. SCHULTZ_HANDLE_NONE means the root.
scalePixels to render for each one the node measures. Two gives a picture twice the size. Must be above zero.
optionsWhat to render with. Must not be NULL.
formatSCHULTZ_IMAGE_PNG or SCHULTZ_IMAGE_BMP.
out_bytesReceives the file's bytes. Must not be NULL. Owned by the toolkit and valid until the next call to schultz_image_encode or to this, so a caller wanting two formats at once copies the first.
out_lengthReceives how many bytes. Must not be NULL.
Returns
SCHULTZ_OK, SCHULTZ_ERR_INVALID_ARGUMENT for a bad argument or a size too large to render, SCHULTZ_ERR_INVALID_HANDLE when the node is not live, or SCHULTZ_ERR_OUT_OF_MEMORY.
