Detailed Description

Font loading and metrics.

Part of the host facing interface. A host binds to schultz_api.h, which includes this header.

A font system owns the FreeType library, the loaded faces, and the handle table that names them. Fonts are identified by handle, never by pointer, so a font destroyed while a widget still refers to it produces an error instead of a crash.

A loaded font binds a face to one pixel size. Two sizes of the same file are two fonts, which keeps metrics and shaping unambiguous.

Loads a face from bytes already in memory.

For a face that never was a file on this machine: one in a resource bundle, an Android asset, a zip, or one that arrived over the network. The bytes are copied, so the caller may free or reuse its buffer as soon as this returns.

Everything else works the same as a face loaded from a file, including asking for it again at another size.

Parameters
systemThe font system to load into. Must not be NULL.
bytesThe face, in any format FreeType reads. Must not be NULL.
lengthHow many bytes. Must not be zero.
size_pxPixel size to bind the face to. Must be above zero.
out_fontReceives the font handle. Must not be NULL.
Returns
SCHULTZ_OK, SCHULTZ_ERR_INVALID_ARGUMENT for a bad argument, SCHULTZ_ERR_UNREADABLE for bytes FreeType would not read, or SCHULTZ_ERR_OUT_OF_MEMORY.

The face compiled into the library for one theme font slot.

Schultz ships three DejaVu faces and one emoji face inside itself, so a program that says nothing about fonts still draws text. They are loaded when the font system is created and live as long as it does.

A host rarely needs this. A theme falls back to these on its own for any font slot nothing was put in, which is the point of them; this is here for a host that wants to name one directly.

Parameters
systemThe font system to ask. NULL yields SCHULTZ_HANDLE_NONE.
tokenOne of SCHULTZ_TOKEN_FONT_BODY, _TITLE, _MONO or _EMOJI.
Returns
The font, or SCHULTZ_HANDLE_NONE for a token that names no slot.

◆ schultz_font_set_emoji()

int32_t schultz_font_set_emoji ( schultz_font_system *  system,
schultz_handle  font 
)

Sets the face that draws emoji.

No text face carries emoji, so a string holding one takes two faces to draw. Shaping splits the string where the chosen face stops having glyphs and gives those parts to this one; the split is made a character at a time as a person sees them, so a flag or a family stays one picture.

The system starts with the face compiled into the library, so this only needs calling by a host that wants its own artwork. The face is asked for at whatever size the text around it is set in, the same way any face is, so one call here covers every size.

This is the only face consulted when the chosen one comes up short, which makes it the answer for emoji and not for a missing script. Text in a script the body font does not cover needs a body font that does.

Parameters
systemThe font system. Must not be NULL.
fontThe face to draw them with, or SCHULTZ_HANDLE_NONE for none, which leaves an emoji to draw as whatever the chosen face shows for a character it does not have.
Returns
SCHULTZ_OK, SCHULTZ_ERR_INVALID_ARGUMENT when system is NULL, or SCHULTZ_ERR_INVALID_HANDLE when the font is not loaded.

Reports whether a face draws a character in colours of its own.

The stronger question, and the one that decides which face draws what. A text face covers a surprising number of emoji as plain outlines, so asking only whether it has the character hands a smiling face to whichever face happens to be asked first and draws it as line art. Asking which face has the colours settles it.

It is also narrower than asking whether the face has colour at all: an emoji face carries the digits and the joiners too, for the sequences they take part in, and those are one colour like any letter.

Parameters
systemThe font system holding the font. NULL yields zero.
fontThe face to ask.
codepointThe Unicode character.
Returns
Nonzero when the face draws it in colour.

◆ schultz_font_at_size()

int32_t schultz_font_at_size ( schultz_font_system *  system,
schultz_handle  font,
float  size_px,
schultz_handle *  out_font 
)

Returns the same face at another pixel size.

A face is bound to one pixel size, because that is what FreeType and HarfBuzz both want, so a font handle names a face and a size together. Asking for another size gives back a handle already loaded at it when there is one, and loads it once otherwise. Sizes are compared after rounding to whole pixels, which is what FreeType is given.

This is what lets font.size in a style mean anything, and what lets a page be rendered at print resolution with its glyphs rasterized at that resolution rather than scaled up from screen size.

Parameters
systemThe system holding the font. Must not be NULL.
fontA font already loaded.
size_pxThe pixel size wanted. Must be greater than zero.
out_fontReceives the handle for that size. Must not be NULL.
Returns
SCHULTZ_OK, SCHULTZ_ERR_INVALID_ARGUMENT, SCHULTZ_ERR_INVALID_HANDLE when the font is not loaded, or SCHULTZ_ERR_OUT_OF_MEMORY.

◆ schultz_font_at_style()

int32_t schultz_font_at_style ( schultz_font_system *  system,
schultz_handle  font,
int32_t  bold,
int32_t  italic,
schultz_handle *  out_font 
)

Returns another member of the same family, at the same size.

The companion to schultz_font_at_size: that one keeps the face and changes the size, this one keeps the size and changes the face.

This is what makes a Bold button possible. A program cannot name the bold handle for whatever the caret is sitting in, because it does not know which face that is, and a selection may cover several. So it asks for bold and italic as a wish, and the family answers with a face.

Which family a face belongs to, and which member of it a face is, both come from the face's own tables. So faces group themselves as they are loaded and nothing has to be declared. The faces compiled into the library include the whole DejaVu Sans family, so bold and italic work with no setup.

Nothing is synthesized. When the family has no member with the styles asked for, the closest one it does have comes back, and a family with nothing closer answers with the face that was passed in. A face that names no family is always its own answer. So this call never fails for want of a face, and a caller can use what it returns without checking which it got.

Parameters
systemThe system holding the font. Must not be NULL.
fontA font already loaded.
boldNonzero for the bold member.
italicNonzero for the italic or oblique member.
out_fontReceives the handle. Must not be NULL.
Returns
SCHULTZ_OK, SCHULTZ_ERR_INVALID_ARGUMENT, SCHULTZ_ERR_INVALID_HANDLE when the font is not loaded, or SCHULTZ_ERR_OUT_OF_MEMORY.
